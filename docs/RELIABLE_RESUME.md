# 이어 하기와 저장 신뢰성

브라우저가 멈추거나, 새로고침하거나, 창을 닫거나, 인터넷이 끊겨도 서버가 이미 확정한 경험치·카드·영토·미션과 풀던 문제를 잃지 않게 하는 방식을 정리한다.

## 원칙

- **판정·보상·소유권은 서버만 확정한다.** 브라우저는 결과를 계산하지 않고, 서버가 확인하기 전에는 "저장됨"이라고 표시하지 않는다.
- 로컬 서버(`server.mjs`)는 요청마다 SQLite에 커밋하고, 공용 Worker는 변경 요청마다 SQLite 파일 전체를 R2에 조건부로 쓴다. 따라서 서버가 응답을 보냈다면(또는 응답을 보내기 직전에 연결이 끊겼더라도) 그 결과는 이미 저장되어 있다.
- 브라우저 보관함은 서버 기록을 대신하지 않는다. 화면 복원과 "아직 보내지 못한 답"을 보관하는 데에만 쓴다.

## 서버

| 기능 | 위치 | 동작 |
| --- | --- | --- |
| 이어 풀 도전 | `lib/game.mjs` `state()` → `activeChallenge` | 답하지 않은 도전을 처음과 같은 공개 모양(같은 보기 순서, `expiresAt` 포함)으로 다시 준다. 정답·해설·허용 답은 넣지 않는다. |
| 만료 | 같은 곳 | 만료 시간(`RULES.challengeTtlMs`, 30분)이 지난 도전은 문제 없이 `{ expired: true }`만 알린다. 되살리지 않는다. 답하면 계속 `challenge_expired`이고 보상은 없다. |
| 답 영수증 | `answer_receipts` 표(`lib/schema.mjs`) | 판정·보상을 커밋하는 **같은 거래** 안에 결과(상태 제외)를 저장한다. 만료로 닫힌 경우도 저장한다. |
| 같은 요청 다시 보내기 | `game.answer(..., { requestId })` | 이미 답한 도전에 **같은 플레이어 + 같은 도전 + 같은 요청 번호 + 같은 답**이 오면 판정·보상을 다시 하지 않고 저장 결과와 현재 상태를 돌려준다(`replayed: true`). 하나라도 다르거나 요청 번호가 없으면 예전처럼 `challenge_used`로 막는다. |
| 영수증 보관 | 같은 곳 | 플레이어마다 최근 5개, 7일까지만 둔다(공용 저장 파일 8MB 제한). 영수증이 지워져도 보상은 이미 서버에 확정되어 있으므로 잃지 않는다. 그때 브라우저는 결과 화면 대신 "이미 처리된 문제"라고 알리고 서버 상태를 다시 불러온다. |
| 로그아웃 | `server.mjs`, Worker `route()` | 쿠키를 지우는 것과 함께 서버의 세션 토큰을 바꿔 **남은 쿠키 복사본도 쓸 수 없게** 한다. |
| 비밀번호 초기화 | Worker `auth.mjs`(기존) | 기존과 같이 세션 토큰을 바꿔 학생의 기존 로그인을 끊는다. |

다시 보내기는 답 제출(`/api/answer`)에만 적용한다. 시장 거래·건물 올리기·시대 발전 같은 다른 변경 요청은 자동으로 다시 보내지 않는다(기존처럼 오류를 보여 주고 학생이 직접 다시 누른다). 이런 요청은 이미 서버에서 중복을 막고 있다(예: 거래 중복 수락 409, `expectedLevel`, 시대 발전 조건 재확인).

## 브라우저 (`public/resume.js`, `public/app.js`)

`localStorage`의 `hta_resume_v1:<player.ref>` 칸에 탐험대별로 보관한다. `player.ref`는 서버가 주는, 비밀이 아닌 짧은 이름표다.

- 보기(점령 지도/역사 지도)와 마지막으로 고른 지역(새 문제를 자동으로 받지는 않음)
- 지금 문제의 공개 모양(문제·보기, 정답 없음)과 단답형 답 초안(입력할 때마다 저장)
- 보내려는 답 `{ requestId, challengeId, answer, status }`. **보내기 전에 먼저 저장한다.**
  - `unsent`: 아직 보내지 못함(오프라인)
  - `sending` / `uncertain`: 보냈지만 서버 확인을 받지 못함. 서버에 닿았을 수도 있다.
- 비밀번호·로그인 토큰은 저장하지 않는다. 로그인 유지는 서버의 HttpOnly 쿠키(30일)가 맡는다. 아이디만 `hta_last_user_v1`에 기억해 로그인 칸을 채운다("다른 학생이에요"로 지울 수 있음).

### 다시 열 때(새로고침·재로그인)

`/api/state`를 받은 뒤 `reconcile(보관함, activeChallenge)`로 맞춘다. 서버가 기준이다.

1. 보낼 답이 있으면 그 문제 화면을 열고 같은 요청 번호로 다시 보낸다.
2. 서버에 이어 풀 도전이 있으면 그 문제를 다시 열고, 같은 도전의 초안만 채운다. 학생이 답하지 않고 닫은 문제는 저절로 다시 열지 않는다.
3. 만료된 도전이면 "만료됐어요"라고 알리고 보관함에서 지운다.
4. 보관함에만 남은 문제(다른 창·기기에서 답했거나 새 문제를 받음)는 지우고 서버 기록을 보여 준다.

### 연결 상태와 다시 보내기

- `online` 이벤트, 화면 다시 보기(`visibilitychange`), 20초 간격(답이 남아 있을 때만)으로 다시 보낸다. 한 탐험대의 답은 한 번에 하나만 보낸다.
- 응답 분류: 성공 → 결과 표시 · 401/임시 비밀번호 변경 필요 → **로그인 필요**(연결 오류처럼 되풀이하지 않고 답을 보관) · `challenge_expired` → 만료 안내 · `challenge_used` → 이미 처리됨, 서버 상태 다시 불러오기 · 429/5xx/동시 요청 409 → 잠시 뒤 다시 · 그 밖의 400 → 답을 다시 고르게 함.
- 머리글의 상태 줄과 문제 창 안의 상태 줄에 한국어로 "보내는 중 · 저장 확인 전", "보내지 못함 · 이 기기에 보관", "보냈지만 확인 못 받음", "서버에 저장했어요"를 구분해 보여 준다.
- 보낼 답이 남아 있으면 새 문제를 받지 않는다(새 문제를 받으면 서버가 이전 도전을 지우기 때문). 먼저 보낸다.

### 로그아웃·학생 바꾸기

- 로그아웃은 서버 세션을 끝낸다. 같은 기기에서 같은 학생이 다시 로그인하면 보관한 초안과 보낼 답을 이어 쓴다.
- "여러 사람이 쓰는 기기예요"를 고르면 이 브라우저의 모든 이어 하기 기록과 기억한 아이디를 지운다(서버 기록은 그대로).
- 다른 학생으로 로그인하면 `player.ref`가 다르므로 이전 학생의 초안·답이 보이지 않는다.
- 닉네임 시연판(`npm start`)은 비밀번호가 없어 쿠키가 유일한 열쇠다. 로그아웃하거나 쿠키를 지우면 그 탐험대로 돌아갈 수 없다고 로그아웃 창에 안내한다.

## 알려진 한계

- 문제를 받은 뒤 30분(만료 시간)이 지나서야 연결되면, 보관한 답은 만료로 처리되어 보상을 받지 못한다. 기기 시계를 믿을 수 없어 오프라인에서 답한 시각을 근거로 받아 주지 않는다. 학생에게 만료를 알리고 새 문제를 받게 한다.
- 오프라인 상태에서 새로고침하면 서비스 워커가 오프라인 안내 화면만 보여 준다(게임 화면 자체는 캐시하지 않음). 보관한 답과 초안은 브라우저에 남아 있다가 연결 뒤 다시 열면 보낸다.
- 객관식·OX는 보기를 누르는 순간이 제출이므로 따로 "고른 보기 초안"은 없다. 누른 답은 보낼 답으로 보관된다.
- 방어 훈련 창(`public/development.js`)은 기존처럼 직접 보낸다. 새로고침 뒤 이어 열 때는 일반 문제 창으로 열리고 이어 하기가 적용된다.
- 브라우저 저장소를 쓸 수 없으면(사생활 보호 모드 등) 보관함은 그 탭 메모리에만 남는다.
- 같은 학생이 다른 기기에서 로그인하면 기존처럼 이전 기기의 세션이 끊긴다(플레이어당 세션 하나).
