# 관리자·가상 학생 시뮬레이션

2026-10-30. 사용자는 사용자 시뮬레이션과 관리자·가상 학생 접근, 검사 통과 후 즉시 게시를 요청했다. 이 작업은 해당 게시 승인을 다시 요구하지 않는다. 다만 현재 제공된 도구에는 기존 Sites 프로젝트를 게시하는 기능/인증 연결이 없어 실제 공개 반영은 수행하지 못했다.

## 연결한 기능

타임퀘스트 로그인 화면의 ‘관리자 · ChatGPT로 로그인’은 기존 `/signin-with-chatgpt` 경로로 본인 확인 후 돌아온다. 서버의 기존 `ADMIN_OWNER_EMAIL` 설정과 인증 헤더가 일치하는 소유자만 기존 관리자 세션을 만들 수 있다. 기존 관리자 아이디·비밀번호로도 로그인할 수 있다. 관리자가 여러 명이면 계정을 선택한다. 관리자로 이미 로그인한 경우 기존 계정을 유지한다. 임의의 이메일·공용 비밀번호·공개 가입 요청으로 관리자 권한을 부여하지 않는다.

관리자 화면에서 ‘가상 학생으로 플레이’를 누르면 기존 `/api/admin/preview-start`를 사용한다. 관리자별 전용 체험 계정은 **학생 권한**으로 전환되며, 새 게임의 기록은 해당 체험 계정에 저장된다. ‘관리자로 돌아가기’는 서버의 별도 복귀 쿠키와 만료·관리자 연결을 검사한다. 체험 기록과 관리자/실제 학생 기록을 합산하지 않는다. 체험 중 로그아웃하면 복귀 쿠키도 지운다.

추가로 로그인 성공 후 `admin-login` URL 표시를 제거한다. 이 표시가 남아 있으면 체험 중 새로고침할 때 관리자 로그인 절차가 다시 시작될 수 있기 때문이다. 관리자·체험 전환은 이동/저장 중에는 비활성화한다.

## 실행한 시뮬레이션

실제 배포할 Worker를 빌드하고 임시 메모리 Bucket으로 브라우저 요청을 처리했다. 브라우저의 관리자 확인 헤더는 테스트 fixture에서만 제공했다. 이는 실제 사용자의 ChatGPT 로그인 검증이나 운영 사이트 접속 결과가 아니다. 운영 비밀값과 실제 학생 데이터는 사용하지 않았다.

1. 일반 학생: 기존 한글 아이디 로그인 → 이동/관찰/정답 → 20 XP 저장 → 로그아웃 → 모바일 브라우저 로그인/새로고침 복원.
2. 관리자: 본인 확인된 소유자 세션 → 관리자 전용 버튼 표시. 일반 학생에게 이 버튼은 보이지 않으며 서버도 관리자 요청을 거절한다.
3. 가상 학생: 전환 후 학생 권한 확인 → 첫 미션 완료/20 XP → 새로고침해도 체험 상태와 기록 유지.
4. 관리자 복귀: 원래 관리자 계정 및 0 XP 복원. 재체험하면 가상 학생의 20 XP 유지. 실제 학생 기록도 유지.
5. 로그아웃: 체험 중 로그아웃 후 복귀 요청 403. 별도 복귀 쿠키 없는 체험 세션 복사본도 복귀 403.
6. 복수 관리자: 새 소유자 세션에서는 계정 선택 UI 표시 → 선택한 관리자 계정으로 입장.

검사 결과: 독립 실행판 서버 검사 11개, 공유 Worker 전체 검사 24개, 독립판 6개 미션 브라우저 및 연결판 사용자/관리자/가상 학생 브라우저 검사 통과. JavaScript 페이지 오류 없음. 가상 상태에서의 통과이며 실제 공개 사이트의 상태를 보증하는 검사는 아니다.

## 재실행과 게시 후 확인

```sh
# online-server/에서
npm run build
npm run validate
node --test test/*.test.mjs
# Playwright/Chromium을 준비한 환경에서
node scripts/timequest-browser.mjs
```

`BROWSER_DRIVER`, `CHROMIUM_PATH`, `ARTIFACT_DIR`로 브라우저 도구와 화면 저장 위치를 지정할 수 있다. 게시할 산출물은 기존과 같은 `dist/server/index.js`, `dist/.openai/hosting.json`이다. 기존 프로젝트·BUCKET·AUTH_PEPPER·ADMIN_OWNER_EMAIL 바인딩을 유지한다.

게시 연결이 제공되면 기존 사이트에 산출물을 게시한 뒤 실제 도메인에서 관리자 ChatGPT 로그인 → 가상 학생 플레이 → 관리자 복귀 및 일반 학생 로그인/이어하기를 다시 확인해야 한다. 현재 GitHub 브랜치 저장이나 환경 스냅샷 게시는 실제 사이트 게시 완료를 의미하지 않는다.
